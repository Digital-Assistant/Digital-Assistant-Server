# Suggested improvements

## A. Audit recipe, framework and tools

1. Engine reads `README.md` only. This repo's file is `README` (no extension). Evidence: import-engine warned "the file README.md is not in the target" (checks/48), EXEC-03 reported "no setup path found" although README lines 18/26 fence `./sync-credentials.sh` and `./start-server.sh`, while HYG-01 found the README. The engine is inconsistent between checks. Fix: one shared README-finder (README, README.md, README.rst, README.txt, case-insensitive) used by EXEC-03, TST-04, EXEC-06, AGT checks and HYG-01.
2. Setup-file search misses `src/main/docker/Dockerfile.jvm` (the Quarkus standard location). EXEC-03 says no Dockerfile exists. Search Dockerfile* at any depth, as EXEC-02 does for lockfiles.
3. EXEC-03 and TST-04 require a fenced block; the rubric text for TST-04 says only "shows". Commands in inline code inside bullets (AGENTS.md:32 single-test command) are missed. Align engine and rubric, or say "fenced" in the rubric.
4. CON-01/CON-02 pick the wrong AGENTS.md section as "prohibitions": evidence points at line 40, `## 3. Architectural Patterns & Code Conventions`, while the real prohibitions section is `## 4. Security & Safety Guardrails` (line 52). CON-01 got the right answer for the wrong reason (it credited architecture paths). Heading matching should key on "must not / forbidden / do not", not on "conventions".
5. SEC-02 treats `Authorization: Bearer sanity.check.invalid` (scripts/ci/smoke-test.sh:55) as a credential and the check doc says Bearer is "unconditional". A deliberately invalid sentinel in a CI smoke test is a recurring pattern; add a guard for `invalid`/`example`/`dummy` token bodies, or a lower-severity finding class.
6. SEC-02 does not flag the opposite case in this repo: tracked `src/main/resources/local.properties` holds `quarkus.datasource.password`, `quarkus.oidc.credentials.secret`, `preflight.postgres.password` (values 4, 6, 9 chars, local-stack only per AGENTS.md) because the unquoted-value guard needs 12+ chars. Short real passwords pass the scan. Consider a path-based rule (`*.properties` with `password|secret` keys and a non-placeholder value) at least as an advisory.
7. SEC-03 does not look at tracked binary key material. `config/keycloak-keystore.jks` is tracked (force-added despite `*.jks` in .gitignore, commit daf0554) and SEC-03/SEC-02 are silent on it. A check for tracked files matching the ignore-pattern list (`git ls-files -ci --exclude-standard`) would catch it.
8. EXEC-04 reports `SECONDS` (bash builtin) as a missing env var. Add shell special variables (SECONDS, RANDOM, LINENO, BASH_*, PIPESTATUS, etc.) to the allow-list. Also it cannot tell optional script inputs (`${IMAGE_TAR:-}`) from required ones; the `:-` default form should be treated as optional.
9. CI-02 returns PASS with detail "CI verbs: none; local read-only verbs not exercised: check, test". CI calls `scripts/ci/test.sh` which runs `./gradlew test`, so the PASS is vacuous (engine did not follow one level of script indirection). Follow `run: scripts/...sh` into the script, as CI-02's own Pitfalls tell the agent to do.
10. CMD-02 for Gradle is UNKNOWN by design; for a build with no custom tasks the answer is derivable (check = test + whatever plugins add). A small plugin-to-task table (java, io.quarkus => test) would let the engine return PARTIAL itself.
11. IDX-01 only looks at opencode/cursor/etc. configs; Claude Code's `~/.claude.json` / `.mcp.json` user-level registration is not read (PASS came from opencode.jsonc). Also IDX-03 is UNKNOWN without `--run-gates`, though the index store exposes `indexed_at` through `index_status`; the recipe could say "compare indexed_at with the HEAD commit time". `detect_changes` failed with "base_branch or HEAD is not a commit" on this repo.
12. Workflow friction: (a) an agent-recorded PASS override over a pending engine finding is refused until a person rejects it (rule 7), which blocks a background Stage 2-3 pass from resolving engine false positives; allow recording an `override_proposal` or let status list "disputed, awaiting rejection". (b) `fr` fragments: `evidence.lines` must be exact; the tool warns for missing files but not for wrong line numbers, so a wrong cite goes through (I had to verify by grep). (c) The recipe says add-finding for "any non-PASS check", but the engine had already imported findings for FAILs and none for UNKNOWN/PARTIAL; the text should say which. (d) stage text says tell the user the run-plan.md path "before asking approval", impossible in a background session; add an unattended note. (e) SKILL.md does not say how to run probes against a disposable clone; the engine runs verbs only on the audited path, so "probe on a clone" means a second report that cannot be imported (target mismatch).
13. Stack profile java.md was verified against this repo on 2026-10-13 (`dev` at 7f351b0). The repo has since gained ci.yml with Gradle build/test, CodeQL, gitleaks and workflow lint, scripts/ci, and a rewritten AGENTS.md. Its Pitfalls and Verified sections (Gemini-only workflows, AGENTS.md describing Maven) are stale for this target; re-verify the profile.
14. Score shape: CMD-02 is a BLOCKER-weight PARTIAL while its finding is DEGRADER (I lowered it because it duplicates F-001), so "7 blockers remaining" in the summary does not match "6 blocker findings". Consider letting a finding inherit "same root cause as F-xxx" to avoid double counting.
15. Evidence rendering: AGT-01 and AGT-10 have empty summaries in the draft (the engine gave no summary text), and engine PASS checks such as EXEC-01, CI-01 carry no evidence items, so Stage 4 has nothing to show for a PASS blocker.

## B. Improvements to the audited project (not captured as findings)

1. Tracked secret-like material: `config/keycloak-keystore.jks` (binary, tracked against .gitignore, referenced only in CONVENTIONS.md) and `src/main/resources/local.properties` with datasource, OIDC client secret and Postgres passwords. Even if local-only, confirm the keystore holds no private key used anywhere real, and consider an untracked `local.properties` generated by `sync-credentials.sh` (the `#local.properties` line in .gitignore is commented out). Repo is open source.
2. `.github/dependabot.yml` says "Versions are locked (lockfiles)" but no Gradle lockfile exists; either enable `dependencyLocking` (fixes F-003 too) or fix the comment.
3. Dependency scan is a no-op: `scripts/ci/scan.sh` prints "skipped" and the `scan` job reports success, so `./gradlew dependencyCheckAnalyze` in AGENTS.md is not in CI. A green "Dependency Scan" job is misleading; rename it or wire OSV/GitHub dependency review.
4. No JDK pin in `build.gradle` (no `java { toolchain }`); CI uses Java 21 via setup-java, local depends on JAVA_HOME. Add a toolchain block.
5. AGENTS.md section 6 (31 of 77 rule lines) is generic role-play prompting; the EntityManager "never inject" rule (line 44) is violated in services/Votes.java:28, SearchList, StatusService, SequenceListService, SearchWithID. Reconcile or document the exceptions. CONVENTIONS.md tree omits scripts/, .github/ and `CLAUDE.md`; AGENTS.md defers to it ("first read CONVENTIONS.md") but nothing loads it automatically (AGT-10).
6. CONTRIBUTING.md still has a placeholder "Add linting and formatting commands here if available". Spotless + Checkstyle (format:check, lint) and a `security` task delegating to dependencyCheckAnalyze would close F-001, F-022..F-024 together; CONVENTIONS.md already fixes tabs/LF/120 columns, so Spotless config is mechanical.
7. Tests need live MariaDB and Elasticsearch (tests are `@QuarkusTest` against 127.0.0.1); an agent cannot run `./gradlew test` without the stack. Documenting a Testcontainers/devservices profile, or a unit-only subset, would give a safe offline verb. This is why no probe was run in this audit.
8. Rename `README` to `README.md` (renders on GitHub either way, but many tools, including the audit engine, look for the extension).
9. Branch protection is not committed; record required status checks (CI Gate) in a runbook the audit can cite (HYG-11/CI-04).

## Notes from landing and Stage 4 (parent session)
- Probes (format:check, lint, typecheck, test) could not run on any repo: `engine.py` runs verbs only against the audited path, and `report.py import-engine` refuses a report whose target differs from the draft's, so a disposable clone cannot be probed. The owner's "disposable worktree" intent is not achievable with the current tools.
- Stage 4 cannot be done before Stage 3 ends if an engine false positive must be disputed: `add-check` to PASS needs the finding rejected first, which needs the owner. A recipe step for "queue disputes" would help background sessions.
- CI gating of this docs landing: all four repos' CI already has a job-level docs-only skip so the required `CI Gate` still reports; `[skip ci]` in a commit would leave the required check pending and block the PR, so it was not used. Gaps: SDK's skip list allows only `*.md`, `artefacts/**`, `LICENSE`, `CHANGELOG.md` (the `.json` report triggers the full gate); Server's `ci.yml` has no docs-only skip. Consider adding `docs/agentic-readiness-report/**` to those filters.
- Owner decisions that differ across repos for the same pattern (CLAUDE.md pointer: rejected in Client and microServices, confirmed in Server) were taken per repo at Stage 4; the engine could not distinguish an `@AGENTS.md` import stub from a shadowing file.
- microServices: owner rejected F-046/F-047 (tracked `environments/local.env` files are intentional for local developer setup). The audit did not verify whether any value in them is live.
